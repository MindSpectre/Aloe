# RACK-TLP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build roadmap phase 2, step 5 (GitHub issue #20): the peer's SACK blocks read into a scoreboard on the retransmission queue's entries, RACK loss detection and the tail loss probe (RFC 8985), one recovery for every connection with PRR for the window (RFC 9937), the undo of a needless reduction, and window growth only while the window is in use; with the scenario runner's line and scripts, the two-stack and tap tests, the benchmark rerun and the docs brought current.

**Architecture:** `SentSegment` gains two marks, reported received and lost, and `RetransmissionQueue` keeps their totals, so what is in flight is arithmetic on the queue. Three new parts of the control block own the new state: `Rack` (time-based detection), `TailProbe` (the probe's flight and its verdict) and `RateReduction` (PRR, held by `LossRecovery`). `LossRecovery` becomes one machine of three states, open, recovery and loss, entered by RACK on a connection that uses SACK and by three duplicate ACKs on one that does not. The AckProcessor runs the ten steps of the spec's "The life of an acknowledgement" and owns no state; the Transmitter owns the resend of any entry, the resend pass, the choice of the one send timer's kind among five, and what each expiry does.

**Tech Stack:** C++26 on libstdc++, clang 22 and GCC 16, CMake and Ninja, GoogleTest, the existing vcpkg dependencies, DPDK 26.03 through `Aloe::Dpdk` inside `ethdev` only. No new dependency.

**Spec:** [Loss recovery with SACK](../specs/2026-11-19-rack-tlp-design.md). Read the spec, `AGENTS.md` and `codestyle.md` before implementation. Both documents live in the git-ignored `docs/superpowers/`; nothing tracked may link to them, and both are force-added to the branch with the pull request. The spec's "Decisions made in the brainstorm" records who decided what; this plan's own choices are marked "plan's call" where the spec's "Left to the builder" left them open.

## Global Constraints

- "A copy of payload on any path that runs without a loss, or a write into a packet the device may still read" is forbidden. Every resend, a probe included, goes through the one resend function, with the busy rule and the copy fallback of step 3.
- "Dropping the packet of an entry the peer reported with a SACK block before a cumulative ACK covers it" is forbidden. An entry marked received keeps its packet and its place in the chain.
- "A resend of an entry the scoreboard holds as received" is forbidden.
- "Two recovery paths that can disagree" is forbidden: one `LossRecovery`, one resend pass, one window rule. A branch on "uses SACK" appears only where a loss is detected and where delivered bytes are counted.
- "A tail probe that counts as a timeout" is forbidden: it moves neither `retransmit_count` nor the RTO's backoff, starts no episode, and is counted in `tail_probes` only.
- Hot paths: every member of `tcp::Stack` and `tcp::Connection` reached after construction is `noexcept`, allocates nothing but packets from IP's pool and nodes from the fixed pools, logs nothing, reads no clock. Errors on hot paths are `std::expected`; constructors throw `std::invalid_argument`.
- The values the spec fixes, verbatim: `tail_probe_ack_delay` 40 ms, rejected when negative or above 500 ms; a probe waits two smoothed round trips, plus the allowance when exactly one segment is in flight, `rto_initial` before the first sample, never later than the RTO's moment; the reordering window is a quarter of the minimum round trip times the multiplier, never more than the smoothed round trip, and zero while reordering has never been seen and the connection is in recovery or has three or more segments reported received; the multiplier persists for 16 recoveries; the minimum round trip is kept over about five minutes (300 s); reneging arms the RTO at `max(srtt / 2, 10 ms)`; at most four SACK blocks are read; NewReno's target on congestion is `max(flight / 2, 2 mss)`; after a timeout the window is what is in flight plus one segment; PRR is RFC 9937 in bytes.
- The congestion window is counted in bytes. Where the plan cites a Linux function, it means that function's rule stated in bytes; where RFC 9937 or RFC 5681 is definite and Linux differs, the RFC stands (spec, "Where this departs from the RFCs and from Linux").
- One departure from an RFC's procedure, by the author's decision: a second tail probe goes once the first probe's end is acknowledged, though its verdict is open, and closes that verdict as a loss (Task 7). It carries a code comment naming RFC 8985 7.3 and 7.4.2 and Linux's `tcp_send_loss_probe`, a counter, and a note on the TCP page (Task 12).
- Scripts are Aloe's own, under `tests/scenarios/tcp/<area>/<name>.pkt`; each opens with a comment stating what it pins and where Linux differs. Every number in a script is derived from the rules under "Read This First", never pasted from a failing run. No script is copied from Linux's corpus.
- Every test runs without root, hugepages or a card; the tap cases and the benchmark rerun are manual.
- `AGENTS.md` rules apply unchanged: `tcp` links neither `execution` nor `log`; `core::TimePoint` and `core::Duration` for every stamp and interval; one class in one place; a header whose names are all in `detail` sits in the `detail/` folder of the folder it belongs to; public headers define no macros; another module's names qualified with its namespace; test helpers in `aloe::testing`; clang-tidy clean inside the clang builds; the include rules of `./scripts/check-includes.sh`.
- `codestyle.md` applies: by-value parameters `const` in definitions and never in bodiless declarations; `[[nodiscard]]` on every value-returning function; a default member initialiser on every struct member; no integer literal suffixes beyond `U`; concepts over SFINAE; a class that models a concept asserts it at the bottom of its header.
- Completion gates: `debug`, `gcc-debug`, `asan` and `tsan` build and pass; `./scripts/check-format.sh` and `./scripts/check-includes.sh` pass; `-DDO_BENCHMARKS=ON` builds and its tests pass; the tap cases and the benchmark rerun are run by hand or recorded as owed.
- Conventional commit subjects with the module as scope: `feat(wire)`, `feat(tcp)`, `refactor(tcp)`, `feat(frames)`, `feat(scenario)`, `test(tcp)`, `bench(tick-to-trade)`, `docs:`.

**The arithmetic every test and script number comes from.** Each line is implemented in exactly one place, named in its task.

```
flight      = SND.NXT - SND.UNA                               sequence space outstanding (SendSequence, unchanged)
reported    = bytes of entries marked received                 with SACK
            = min(duplicates * mss, flight - max(lost, mss))   without SACK: one segment per duplicate ACK since
                                                               SND.UNA last moved, a hole of one segment kept
lost        = bytes of entries marked lost and not resent since
in_flight   = flight - reported - lost
room        = min(SND.WND - flight, window - in_flight), each floored at zero     what writable() offers, capped at mss
may send    = in_flight < window                               a resend, and the first byte of new data (RFC 9937)
window      = the policy's, outside recovery; in recovery, PRR's when the policy's target is bounded
```

PRR, RFC 9937 6.2, with `target` the policy's `ssthresh` and `mss` the connection's:

```
on entering recovery:  prr_delivered = 0; prr_out = 0
                       RecoverFS = flight - (bytes marked received by blocks)
                                   + (bytes this ACK newly marked by a block) + (bytes it newly acknowledged)
                       without SACK no block marks anything, so RecoverFS = flight;
                       with no ACK (the reordering timer) the window is in_flight + mss and no step runs
per ACK in recovery:   if delivered == 0: return
                       prr_delivered += delivered
                       if in_flight > target:   SndCnt = ceil(prr_delivered * target / RecoverFS) - prr_out
                       else:                    SndCnt = max(prr_delivered - prr_out, delivered)
                                                if safe: SndCnt += mss
                                                SndCnt = min(target - in_flight, SndCnt)
                       if prr_out == 0 and SndCnt == 0: SndCnt = mss
                       window = in_flight + SndCnt         (SndCnt below zero counts as zero)
per send in recovery:  prr_out += bytes sent, new or resent
on leaving recovery:   window = target
delivered              = (SND.UNA's advance) + (the change in reported)        with SACK
                       = mss per duplicate ACK; on an advance, the advance less mss per preceding duplicate,
                         and never so much that prr_delivered passes RecoverFS  without SACK
safe                   = the ACK moved SND.UNA and nothing was newly marked lost on it
```

The timers, all on the connection's one send timer; `rto_at` is the moment the RTO would fire, set wherever the RTO is armed today (`now + rto`, under the user timeout):

```
tail probe  = min(now + 2 * srtt + (exactly one segment in flight ? tail_probe_ack_delay : 0), rto_at)
              now + rto_initial instead of 2 * srtt before the first sample
reordering  = min(now + the longest wait RACK left, rto_at)
RACK's wait = entry.sent + rack_rtt + reordering_window - now          for an entry sent before RACK's segment
reo. window = 0 while reordering was never seen and (in recovery or loss, or 3 or more segments reported)
              else min(min_rtt / 4 * multiplier, srtt)
reneging    = now + max(srtt / 2, 10 ms), as the RTO kind
```

The wheel rounds every deadline up to its 1 ms tick, and a deadline at or before the last processed tick fires on the next `advance`.

- A member of a class template that is declared but never defined fails at link time only once something instantiates it; `tcp::Stack::process` reaches the whole receive path and the timers the whole transmit path, so every function a task declares is defined in the same task.

- `TcpFixture`'s stack port holds 64 packets. A test that keeps many entries unacknowledged while it receives stays under that, or pins `send_segments`.
- `send_nodes_available()` on an open connection is one short of `send_pool`: a node is set aside for the FIN.

## How to Execute and Review

Use superpowers:subagent-driven-development (preferred) or superpowers:executing-plans. One task at a time, in order; each ends with every listed test passing on `debug` and a commit. Before writing a part that the spec ties to Linux, read the Linux function the task names (the table above gives what was relied on) and stop if it no longer says what the table says.

1. **Spec conformance.** The task's interfaces match this plan's Interfaces blocks exactly; the behaviour matches the spec sections the task cites; the values of "Global Constraints" appear verbatim; a departure from an RFC or from Linux is one the spec's "Where this departs" lists, with its comment in the code.

3. **Owned state.** Each new field sits in the part that owns its concern, with the operations on it; the AckProcessor gains procedure and no fields; the Transmitter gains no state beyond what it has; no part reaches into another's members.

```cpp
/// The newest entry that was transmitted: the tail, or the entry before a FIN that waits for the window.
[[nodiscard]] std::uint32_t last_sent(const Pool& pool) const noexcept;
[[nodiscard]] bool head_reported(const Pool& pool) const noexcept;

[[nodiscard]] std::uint32_t reported_bytes() const noexcept;
[[nodiscard]] std::uint32_t reported_segments() const noexcept;
[[nodiscard]] std::uint32_t lost_bytes() const noexcept;
```

```cpp
class Rack {
public:
    /// What one detection did.
    struct Detected {
        std::uint32_t marked       = 0;  ///< Entries newly marked lost.
        std::uint32_t resends_lost = 0;  ///< Of them, resends marked again.
        core::Duration wait{};           ///< The longest wait left among entries not yet due; zero when none waits.
    };

    /// A round-trip sample: the minimum over about five minutes, kept as two windows of 300 s.
    void sample(core::Duration round_trip, core::TimePoint now) noexcept;
    /// An entry was newly reported, by a block or by the cumulative ACK: `sent` its last transmission, `end` its
    /// end sequence. Skipped when it was resent and `now - sent` is below the minimum round trip, or
    /// `echo_before_resend` (a cumulative ACK whose echo is older than the resend). Otherwise RACK's round trip
    /// is `now - sent`, and its stamp and end are taken when later, by stamp and then by sequence.
    void advance(core::TimePoint sent, wire::TcpSequence end, bool resent, bool echo_before_resend,
                 core::TimePoint now) noexcept;
    void see_reordering() noexcept;
    [[nodiscard]] bool reordering_seen() const noexcept;
    /// RFC 8985's `RACK_update_reo_wnd`, the part an ACK drives: a round that began at `nxt` ends when `una`
    /// reaches it; a believed duplicate report that is not a probe's, once reordering was seen and outside such
    /// a round, grows the multiplier by one, starts a round at `nxt` and sets the persistence to 16.
    void on_ack(wire::TcpSequence una, wire::TcpSequence nxt, bool duplicate_report) noexcept;
    /// A recovery ended and was not undone: the persistence drops, and at zero the multiplier is one again.
    void recovery_ended() noexcept;
    /// An undo by duplicate SACK: the persistence rises by one, to at most 16.
    void undone_by_report() noexcept;
    /// The reordering window, as "Read This First" states it.
    [[nodiscard]] core::Duration window(bool recovering, std::uint32_t reported_segments,
                                        std::optional<core::Duration> srtt) const noexcept;
    /// RACK's state moved since the last detection.
    [[nodiscard]] bool advanced() const noexcept;
    /// Marks every entry that is neither reported nor waiting for its resend, was sent before RACK's segment,
    /// and whose time has passed: `sent + round trip + window <= now`. Walks from the head and stops at the
    /// first entry that never was resent and was not sent before RACK's segment.
    template <device::IsPacket Packet>
    [[nodiscard]] Detected detect(RetransmissionQueue<Packet>& queue, SentSegmentPool<Packet>& pool,
                                  core::Duration window, core::TimePoint now) noexcept;
    [[nodiscard]] core::Duration round_trip() const noexcept;
    [[nodiscard]] std::optional<core::Duration> min_round_trip() const noexcept;
};
```

```cpp
class TailProbe {
public:
    /// What an ACK settled.
    enum class Verdict : std::uint8_t { Open, Needless, Repaired };

    /// RFC 8985 7.2: two smoothed round trips, `initial` before a sample, plus `allowance` for one segment.
    [[nodiscard]] static core::Duration wait(std::optional<core::Duration> srtt, bool one_segment,
                                             core::Duration allowance, core::Duration initial) noexcept;
    /// A probe may leave: none is in flight, and a round-trip sample was taken since the last.
    [[nodiscard]] bool may_probe() const noexcept;
    [[nodiscard]] bool in_flight() const noexcept;
    [[nodiscard]] bool verdict_open() const noexcept;
    /// The probe's end, while its verdict is open.
    [[nodiscard]] std::optional<wire::TcpSequence> end() const noexcept;
    /// A probe left with SND.NXT at `end`: in flight, verdict open, no sample since.
    void sent(wire::TcpSequence end) noexcept;
    /// A round-trip sample was taken.
    void sampled() noexcept;
    /// RFC 8985 7.4's `TLP_process_ack`. `ack` at or past the end takes the probe out of flight. Then:
    /// `duplicate_for_probe` closes the verdict as needless; `ack` past the end closes it as repaired; a
    /// `plain_duplicate` (no advance, no data, no block) closes it as needless; otherwise it stays open.
    [[nodiscard]] Verdict on_ack(wire::TcpSequence ack, bool duplicate_for_probe, bool plain_duplicate) noexcept;
    /// A recovery or a timeout began, or the connection ended: nothing in flight, no verdict.
    void forget() noexcept;
};
```
