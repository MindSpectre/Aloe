# IPv4 Brick Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Carve `net::Ipv4<Device>` (776 lines, one class) into a façade over four parts in `aloe::net::detail`, each in `common/net/detail/`, with no observable change: same public types and members, same counters, same tests.

**Architecture:** `Ipv4` keeps its public face, the config, the counters and the queue reference, and owns four parts constructed in dependency order: `detail::Routing` (the subnet, the gateway and the broadcast rules: pure queries), `detail::Arp<Device>` (the cache, the request, the reply, the learn paths and the `resolved()` list), `detail::Output<Device>` (`send`, `prebuild`, `send_frame`, the checksums, the identification counter) and `detail::Input<Device>` (frame dispatch, the IPv4 checks, delivery into the transport lists, the echo reply). The arrows run one way: Input → Output, Input → Arp, Output → Arp, Arp → the queue alone; Routing is read by Input and Output. The counters are one struct the façade owns and every part writes through a reference, as `tcp::detail::SegmentWriter` does today.

**Tech Stack:** C++26 (clang and GCC 16), CMake presets, gtest; no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-09-stack-split-design-draft.md`, decisions 7, 8 and 9 and the "Delivery and documentation" section. This plan is the first of the two pull requests the spec orders; the TCP plan (`2026-11-09-tcp-split.md`) follows it.

## Global Constraints

- **A pure refactor.** No public type, member, constant or counter of `aloe::net` changes name, type or meaning; no test file under `tests/` changes; every moved function keeps its body except for the substitutions each task lists. A test that would have to change is a sign the split changed behaviour: stop and report it.
- **The dependency direction is read off the includes.** `detail/ipv4_arp.hpp` includes no other part; `detail/ipv4_output.hpp` includes `ipv4_arp.hpp` and `ipv4_routing.hpp`; `detail/ipv4_input.hpp` includes `ipv4_arp.hpp`, `ipv4_output.hpp` and `ipv4_routing.hpp`; `stack/ipv4.hpp` includes all four. Nothing in `detail/` includes `ipv4.hpp`.
- **The `detail/` rule (spec decision 9).** Every header whose names are all in `aloe::net::detail` sits in `common/net/detail/` and is included as `#include <detail/name.hpp>`; the module root joins the target's include directories. A header with a public name stays where it is.
- **Hot paths.** Every member of the brick and its parts reached after construction is `noexcept`, allocates nothing but packets from the queue's pool, logs nothing, reads no clock; errors are `std::expected`; constructors throw `std::invalid_argument`.
- **`AGENTS.md` and `codestyle.md` apply unchanged:** one class in one header with its members in its body; another module's names qualified (`wire::`, `device::`, `loop::`, `core::`); a `.cpp` includes its own header in quotes, a same-module header by basename or `<detail/name.hpp>`, another module through its umbrella; `std::unique_ptr` for owned memory, `T&` for a link the constructor sets that is never null and never changes, `T*` only for one that can be null or is set later; public headers define no macros; `[[nodiscard]]` on every value-returning function; by-value parameters `const` in definitions; private data members end in `_`, public struct members do not; a default member initialiser on every struct member; no integer literal suffixes beyond `U` on shift counts.
- **Commits:** conventional subjects with the module as scope, `refactor(net): ...` for the code and `docs(net): ...` for the pages. **Pull request:** `[NET] Split the IPv4 brick into routing, ARP, output and input parts`.

Why the bodies are not repeated here: every function this plan moves exists on `main` at the lines the Verified table gives, and each task says which lines move where and which identifiers change. The implementer moves the text and applies the substitutions; the compiler, the tests and the reviewer's diff catch the rest. New code (the parts' class skeletons, constructors and accessors, the façade's forwarding members, the CMake and umbrella lines) is written out in full.

Code-base traps that bite this plan in particular; the full list is in `AGENTS.md`:

- **A member of a class template declared and never defined** fails only at link time, once something instantiates it. Every member a part declares is defined in its body in the same task.
- **`loop::ShardQueue::transmit(Packet&&)` moves only on success.** The three `NOLINTBEGIN/END(bugprone-use-after-move)` blocks in `send` and `send_frame` move with those functions, unchanged.
- **clang-tidy's `readability-make-member-function-const`** fires on a member that only writes through a reference or pointer member, and it fires inside class templates (`loop::ShardQueue` and `Ipv4::allocate` carry `core::force_non_const(this)` for that reason). A part owns none of the queue, the counters or another part, so a member that touches only those becomes `const` (the rule for a non-owning handle, as `log::Logger`): expect it on `Arp::request_arp`, `Output::prebuild`, `Output::finish_checksums` and `Input::receive_icmp`, and on whatever else clang-tidy names. A member that writes the part's own state (`identification_`, `cache_`, `resolved_`, `tcp_`, `udp_`) stays non-const. Do not write `core::force_non_const(this)` in a part: it claims ownership the part does not have; the façade keeps it in `allocate()`.
- **GCC's `-Wshadow`** warns when a constructor parameter shadows a member function: a part with an accessor `routing()` or `counters()` must not take a parameter of that name. The skeletons below name parameters so that this does not arise.
- **`-Wreorder` and the reference members.** Every part holds references to what the façade constructs before it: in `Ipv4` the declaration order is `queue_`, `config_`, `routing_`, `counters_`, `arp_`, `output_`, `input_`, and the initialiser list follows it. Today `counters_` is declared last; it moves before the parts.
- **clang's `-Wmissing-designated-field-initializers`** is an error: a struct member gets a default member initialiser.
- **The `--staged` pre-commit hook** runs the format and include checks on the staged files; a commit that fails them is refused, so run both scripts before `git commit`.
- **Stale objects after a layout change.** If a binary aborts for no visible reason after a header moved, rebuild with `cmake --build --preset debug --clean-first` before chasing it.

- [ ] **Step 1: Create `common/net/detail/ipv4_routing.hpp`**

```cpp
#pragma once

#include <aloe/wire>
#include <cstdint>
#include <optional>

namespace aloe::net::detail {

    /**
     * @brief Where a unicast datagram goes and which addresses are ours: the subnet, the gateway and the two
     * broadcasts, as route questions with no side effect. `Ipv4::send` and `Ipv4::prebuild` decide the same way.
     */
    class Routing {
    public:
        Routing(const wire::Ipv4Address address,
                const std::uint8_t prefix,
                const std::optional<wire::Ipv4Address> gateway) noexcept
            : address_{address},
              subnet_{address, prefix},
              gateway_{gateway} {
        }

        /// The destination itself on the subnet, the gateway off it, or nothing when there is none. Broadcast and
        /// multicast destinations are not routed and answer with themselves.
        [[nodiscard]] std::optional<wire::Ipv4Address> next_hop(wire::Ipv4Address destination) const noexcept;
        /// The limited broadcast, or the subnet broadcast where the subnet has one.
        [[nodiscard]] bool is_broadcast(wire::Ipv4Address address) const noexcept;
        /// Our unicast address or a broadcast.
        [[nodiscard]] bool for_me(wire::Ipv4Address destination) const noexcept;

        [[nodiscard]] wire::Ipv4Address address() const noexcept {
            return address_;
        }
        [[nodiscard]] const wire::Ipv4Subnet& subnet() const noexcept {
            return subnet_;
        }
        [[nodiscard]] std::optional<wire::Ipv4Address> gateway() const noexcept {
            return gateway_;
        }

    private:
        wire::Ipv4Address address_;
        wire::Ipv4Subnet subnet_;
        std::optional<wire::Ipv4Address> gateway_;
    };

}  // namespace aloe::net::detail
```

namespace aloe::net::detail {

    /// Transmits a frame a part built in `packet`: counts it under `sent`, or under `refused` when the queue and
    /// the device are both full, in which case the packet goes back to its pool.
    template <device::IsDevice Device>
