# TCP Stack Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Carve `tcp::Stack<Ip, CongestionControl>` (1646 lines, one class) into a façade over three procedure classes, `detail::Receiver`, `detail::Lifecycle` and `detail::Transmitter`, working on one `detail::ControlBlock` per connection and one `detail::StackContext` per shard, with every header whose names are all in `detail` under `common/tcp/detail/`, and no observable change: same public types and members, same counters, same scripts, same tests.

**Architecture:** The per-connection state `tcp::Connection` holds privately today becomes a struct, `detail::ControlBlock<Ip, CongestionControl>`, in a deque the stack's context owns; `Connection` becomes the public handle over one block, forwarding its verbs to the stack as it does now. The procedure splits by responsibility with the dependency running one way, Receiver → Lifecycle → Transmitter, the direction of Linux's `tcp_input.c` and `tcp_timer.c` into `tcp_output.c`: the Transmitter (every segment that leaves, the retransmission queue and its pool, the ACK, retry and deferred lists, the timers' arming, `writable`/`prepare`/`commit`) names neither of the other two; the Lifecycle (the connection table, the ISN generator, the event list; slots in and out, the states to `Closed`, `close`/`abort`/`release`, the timer expiries) calls down into the Transmitter; the Receiver (what a datagram does to a connection, the ACK processing, `consume`) calls both. `Stack` keeps `process`, `flush`, `connect`, `listen`, `poll_event` and the accessors, owns the context and the three parts, and maps a block to its handle. Triggers from the receive side to the transmit side stay direct calls; state defers work only where the stack already defers it (the three lists).

**Tech Stack:** C++26 (clang and GCC 16), CMake presets, gtest, the scenario runner; no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-09-stack-split-design-draft.md`, decisions 1 to 6, 8 and 9, "The TCP brick after the split", "Hazards", "Testing", "Delivery and documentation". This is the second of the two pull requests the spec orders; the IPv4 plan (`2026-11-09-ipv4-split.md`) comes first and sets the `detail/` pattern.

## Global Constraints

- **A pure refactor.** No public type, member, constant, counter or event of `aloe::tcp` changes name, type or meaning; no test, fixture, scenario script or example changes; every moved function keeps its body except for the substitutions R1 to R5 below. A test that would have to change is a sign the split changed behaviour: stop and report it.
- **The dependency direction is read off the includes.** `detail/transmitter.hpp` includes `control_block.hpp`, `stack_context.hpp`, `segment_writer.hpp`, `sent_segment_pool.hpp` and no other part; `detail/lifecycle.hpp` includes `transmitter.hpp`, `connection_table.hpp`, `isn_generator.hpp`; `detail/receiver.hpp` includes `lifecycle.hpp` and `transmitter.hpp`; `stack/tcp_stack.hpp` includes all three. Nothing in `detail/` includes `tcp_stack.hpp` or `tcp_connection.hpp`.
- **Triggers are direct calls (spec decision 3).** The immediate ACK, the fast retransmit, the SYN-ACK, the stray-segment RST and the FIN a window update releases are sent in place, where the code sends them today. No flag, no drain pass, no reordering against the next datagram of a burst.
- **The control block is single-thread state (spec decision 4).** No atomic, no lock, no "shared" marking, no comment that suggests another core reads it.
- **The `detail/` rule (spec decision 9).** Every header whose names are all in `aloe::tcp::detail` sits in `common/tcp/detail/` and is included as `#include <detail/name.hpp>`; the module root joins the target's include directories; `tcp_fwd.hpp`, which mixes public and `detail` names, stays in `stack/`.
- **Hot paths.** Every member reached after construction is `noexcept`, allocates nothing but packets from IP and nodes from the two fixed pools, logs nothing, reads no clock; errors are `std::expected`; the constructor throws `std::invalid_argument`.
- **`AGENTS.md` and `codestyle.md` apply unchanged:** one class in one header with its members in its body; another module's names qualified; the include spellings; `T&` for a link the constructor sets that is never null and never changes, `T*` only for one that can be null or is set later, no `std::shared_ptr`; public headers define no macros; `[[nodiscard]]` on every value-returning function; `const` by-value parameters in definitions; private data members end in `_`, public struct members do not; a default member initialiser on every struct member; no integer literal suffixes beyond `U` on shift counts; `tcp` links neither `execution` nor `log` and names neither.
- **Commits:** `refactor(tcp): ...` for the code, `docs(tcp): ...` for the pages. **Pull request:** `[TCP] Split the stack into Receiver, Lifecycle and Transmitter over a control block`.

Why the bodies are not repeated here: every function this plan moves exists on `main` at the lines the Verified table gives, and each task says which lines move where and which identifiers change. The implementer moves the text and applies the substitutions; the compiler, the tests and the reviewer's diff catch the rest. New code (the block, the context, the three parts' skeletons, the handle, the façade, the CMake and umbrella lines) is written out in full.

**The substitution rules**, named once and cited by every task:

- **R1 (Task 2):** a parameter `ConnectionType& conn` becomes `Block& block` and `const ConnectionType& conn` becomes `const Block& block`; every `conn.` in the body becomes `block.`; a loop variable `ConnectionType* c` becomes `Block* c`; an index into `connections_` to find the state (`connections_[*found]`, `connections_[*slot]`) becomes an index into the blocks.
- **R2 (Task 2):** the block's members carry no trailing underscore: `state_` → `state`, `owned_` → `owned`, `indexed_` → `indexed`, `local_` → `local`, `remote_` → `remote`, `key_` → `key`, `base_hash_` → `base_hash`, `template_` → `frame`, `events_` → `events`, `event_link_` → `event_link`, `ack_link_` → `ack_link`, `retry_link_` → `retry_link`, `deferred_link_` → `deferred_link`, `finish_pending_` → `finish_pending`, `receive_` → `receive`, `ack_policy_` → `ack_policy`, `send_` → `send`, `prepared_` → `prepared`, `queue_` → `queue`, `recovery_` → `recovery`, `rtt_` → `rtt`, `probe_` → `probe`, `timestamps_` → `timestamps`, `timer_` → `timer`, `timer_kind_` → `timer_kind`, `retransmit_count_` → `retransmit_count`, `unresolved_polls_` → `unresolved_polls`, `index_` → `index`, `stack_` → `stack`.
- **R3 (Task 2):** the queries the stack read from the handle move to the block: `conn.mss()` → `block.mss()`, `conn.probing()` → `block.probing()`, `conn.timestamps()` → `block.timestamps_negotiated()`.
- **R4 (Task 3):** the shared services move into the context: `config_` → `context_.config`, `counters_` → `context_.counters`, `now_` → `context_.now`, `pool_` → `context_.pool`, `mss_` → `context_.mss`, `byte_budget_` → `context_.byte_budget`, `ip_` → `context_.ip`, `blocks_` → `context_.blocks`.
- **R5 (Tasks 4-6):** a call to a function that now lives in another part takes that part's prefix (`transmitter_.`, `lifecycle_.`); a read of state another part owns goes through the accessor its Interfaces block names (`transmitter_.in_flight(block)`, `transmitter_.head(block)`, `transmitter_.deferred(block)`, `transmitter_.ack_pending(block)`, `transmitter_.nodes_available()`, `lifecycle_.table()`).

Code-base traps that bite this plan in particular; the full list is in `AGENTS.md`:

- **A member of a class template declared and never defined** fails only at link time, once something instantiates it, and `Stack::process` reaches the whole receive path: every member a part declares is defined in its body in the same task, and `ctest` runs after every task.
- **Stale objects after a layout change.** The scenario binaries once aborted (a RST for a SYN, then `free(): invalid size`) after a struct the stack compiles in changed shape, and passed after `cmake --build --preset gcc-debug --clean-first`. Tasks 2 and 3 change the layout: rebuild clean before chasing an abort.
- **`loop::ShardQueue::transmit(Packet&&)` moves only on success**; the `NOLINT(bugprone-use-after-move)` lines in the send path move with their functions unchanged.
- **clang-tidy's `cppcoreguidelines-pro-type-static-cast-downcast`** has `StrictMode` off, so the `static_cast<TimerNode&>(timer)` in the trampoline stays as it is today.
- **clang-tidy's `readability-make-member-function-const`** fires on a member that only writes through a reference or pointer member, and it fires inside class templates (`loop::ShardQueue` and `net::Ipv4::allocate` carry `core::force_non_const(this)` for that reason). A part's member that writes only its `Block&` parameter and goes through the part's references (`context_`, `wheel_`, `transmitter_`, `lifecycle_`) will be flagged: add `const`, which is `AGENTS.md`'s rule for a non-owning handle. Expect it on most of the Receiver, on the Transmitter's timer arming and on the Lifecycle's state changes that touch no list; a member that writes state the part owns (the Transmitter's pool, lists and writer; the Lifecycle's table, ISN and events) stays non-const. Do not write `core::force_non_const(this)` in a part: it claims ownership the part does not have. The façade's `force_recover` keeps its `core::force_non_static`.
- **GCC's `-Wshadow`** warns when a constructor parameter shadows a member function. The skeletons name the parameters so this does not arise (`owner`, `ip_brick`, `validated`); keep them.
- **`-Wreorder` and the reference members.** The context is declared first in `Stack`, the Transmitter second, the Lifecycle third, the Receiver fourth, the deque of handles last; each initialiser list follows its declaration order.
- **clang's `-Wmissing-designated-field-initializers`** is an error; the block's and the context's data members all carry default member initialisers except the references and the timer node, which the constructor sets.
- **The passkey.** `Connection`'s constructor takes `PrivateTag`, which only `Stack` names (`friend class Stack`); the deque of handles therefore stays the stack's, and the parts never construct or name a `Connection`.
- **The `--staged` pre-commit hook** runs the format and include checks; run both scripts before `git commit`.
- **A gtest filter:** `-` starts the excluded patterns, so a script with a dash in its name is matched with `?`.

```cpp
#include <tcp_fwd.hpp>

namespace aloe::tcp::detail {

    /// What the connection's one wheel timer does when it fires.
    enum class TimerKind : std::uint8_t {
        None,        ///< Not armed.
        Retransmit,  ///< The RTO: the head of the retransmission queue goes again.
        ArpPoll,     ///< A SYN, SYN-ACK or FIN whose first send found no next hop: the send is tried again.
        Probe,       ///< The peer's window is zero and nothing is in flight: a zero-window probe goes.
    };

    /**
     * @brief One connection's state, RFC 9293's transmission control block: the identity, the events and the
     * list links, the protocol's parts one per concern, and the one wheel timer.
     *
     * Plain single-thread memory that the stack's three parts read and write on the shard's thread; nothing in it
     * is shared across threads. `tcp::Connection` is the public handle over one block; the stack owns the blocks in
     * a deque, one per slot, and maps a block back to its handle through `index`.
     */
    template <typename Ip, typename CongestionControl>
    struct ControlBlock {
        using Packet = Ip::Packet;

        /// An open preparation: the packet the application writes into and the bytes it may commit.
        struct Preparation {
            Packet packet{};
            std::size_t size = 0;
        };

        /// The wheel's node, carrying the way back to its block.
        struct TimerNode : loop::Timer {
            /// `callback`, not `fire`: a parameter named `fire` shadows `loop::Timer::fire` under GCC's `-Wshadow`.
            TimerNode(const loop::Timer::Function callback, ControlBlock& owner) noexcept
                : loop::Timer{callback},
                  block{owner} {
            }

            ControlBlock& block;
        };

        /// `fire` is the stack's trampoline; `slot` the block's index in the stack's deque; `stack_mss` the stack's.
        ControlBlock(Stack<Ip, CongestionControl>& owner,
                     const loop::Timer::Function fire,
                     const std::uint32_t slot,
                     const std::uint16_t stack_mss) noexcept
            : stack{owner},
              index{slot},
              local_mss{stack_mss},
              timer{fire, *this} {
        }

        ControlBlock(const ControlBlock&)            = delete;
        ControlBlock& operator=(const ControlBlock&) = delete;
        ControlBlock(ControlBlock&&)                 = delete;
        ControlBlock& operator=(ControlBlock&&)      = delete;
        ~ControlBlock()                              = default;

        /// The payload a segment carries: the smaller of the peer's MSS option and ours, less the timestamp option
        /// once the connection sends it. The SYN's MSS option keeps the full value.
        [[nodiscard]] std::uint16_t mss() const noexcept {
            const std::uint16_t negotiated = std::min(send.peer_mss, local_mss);
            const std::uint16_t options    = timestamps_negotiated()
                                                 ? static_cast<std::uint16_t>(wire::TcpOptions::timestamps_size)
                                                 : std::uint16_t{0};
            return static_cast<std::uint16_t>(negotiated - std::min(negotiated, options));
        }
        /// RFC 7323 timestamps were negotiated: both ends offered them in the handshake and the config allows them.
        [[nodiscard]] bool timestamps_negotiated() const noexcept {
            return timestamps.enabled() && state != State::SynSent;
        }
        /// The peer's window is zero with nothing in flight: the timer sends zero-window probes until it opens.
        [[nodiscard]] bool probing() const noexcept {
            return timer_kind == TimerKind::Probe;
        }

        /// Back to the state of a fresh slot; the stack, the index, the MSS and the timer trampoline stay. The stack
        /// unlinks the block from its lists, returns the held packets and drops the queue first.
        void clear() noexcept;  // Connection::clear (tcp_connection.hpp:222-251) under R2

        // Identity and ownership.
        Stack<Ip, CongestionControl>& stack;
        std::uint32_t index     = 0;
        std::uint16_t local_mss = 0;  ///< The stack's MSS: `max_l4_size() - 20`.
        State state             = State::Closed;
        bool owned              = false;  ///< An application holds it: after Accepted, or from connect.
        bool indexed            = false;  ///< Its key is in the flow table.
        Endpoint local{};
        Endpoint remote{};
        FlowKey key{};
        std::uint32_t base_hash = 0;
        FrameTemplate frame{};  ///< The link and network headers of every segment to the peer.

        // Events and the stack's lists; being on the ACK list is having an ordinary ACK wait for flush.
        stream::Events events{};
        Link<ControlBlock> event_link{};
        Link<ControlBlock> ack_link{};
        Link<ControlBlock> retry_link{};
        Link<ControlBlock> deferred_link{};  ///< A resend found its packet lent; the next flush tries again.
        bool finish_pending = false;  ///< The protocol is done; Closed is raised once the last ACK is queued.

        // The protocol's state, one part per concern.
        ReceiveQueue<Packet> receive{};
        AckPolicy ack_policy{};
        SendSequence send{};
        std::optional<Preparation> prepared{};
        RetransmissionQueue<Packet> queue{};
        LossRecovery<CongestionControl> recovery{};
        RttEstimator rtt{};
        ZeroWindowProbe probe{};
        Timestamps timestamps{};

        // The one wheel timer: the RTO, the ARP poll or the probe.
        TimerNode timer;
        TimerKind timer_kind            = TimerKind::None;  ///< What `timer` does when it fires.
        std::uint8_t retransmit_count  = 0;  ///< Expiries since the last ACK of new data, deferred and refused too.
        std::uint16_t unresolved_polls = 0;  ///< Polls since the last send that left; the config bounds them.
    };

}  // namespace aloe::tcp::detail
```

```cpp
namespace aloe::tcp::detail {

    /**
     * @brief What every part of the stack reads: the IP brick, the validated config and what is derived from it,
     * the pool of held segments, the blocks, the counters and the stamp of the last `process`, `flush` or
     * `connect`. One per shard, owned by the stack, held by reference by its parts.
     */
    template <typename Ip, typename CongestionControl>
    struct StackContext {
        using Packet = Ip::Packet;
        using Block  = ControlBlock<Ip, CongestionControl>;

        /// `validated` is the config after `TcpConfig::validate`; one block per slot is built here over `owner`.
        StackContext(Ip& ip_brick,
                     const TcpConfig& validated,
                     Stack<Ip, CongestionControl>& owner,
                     const loop::Timer::Function fire)
            : ip{ip_brick},
              config{validated},
              mss{static_cast<std::uint16_t>(ip_brick.max_l4_size() - wire::TcpHeader::size)},
              byte_budget{static_cast<std::uint32_t>(std::min<std::uint64_t>(
                  std::uint64_t{config.receive_segments} * mss, std::numeric_limits<std::uint16_t>::max()))},
              pool{config.receive_pool} {
            for (std::size_t index = 0; index < config.connections; ++index) {
                blocks.emplace_back(owner, fire, static_cast<std::uint32_t>(index), mss);
            }
        }

        StackContext(const StackContext&)            = delete;
        StackContext& operator=(const StackContext&) = delete;
        StackContext(StackContext&&)                 = delete;
        StackContext& operator=(StackContext&&)      = delete;
        ~StackContext()                              = default;

        Ip& ip;
        TcpConfig config;
        std::uint16_t mss         = 0;  ///< Ours: `max_l4_size() - 20`.
        std::uint32_t byte_budget = 0;  ///< `min(receive_segments * mss, 65535)`: the receive credit a connection starts with.
        HeldSegmentPool<Packet> pool;
        std::deque<Block> blocks{};
        TcpCounters counters{};
        core::TimePoint now{};
    };

}  // namespace aloe::tcp::detail
```

```cpp
    template <typename Ip, typename CongestionControl>
    class Stack {
        // the five static_asserts, unchanged

    public:
        // the six aliases, unchanged

        /// Validates and throws std::invalid_argument; allocates everything; sends nothing.
        Stack(Ip& ip, loop::TimerWheel& wheel, const TcpConfig& config)
            : context_{ip, config.validate(ip.max_l4_size(), wheel.resolution()), *this, &Stack::on_timer_fired},
              transmitter_{context_, wheel},
              lifecycle_{context_, transmitter_},
              receiver_{context_, lifecycle_, transmitter_} {
            for (Block& block : context_.blocks) {
                connections_.emplace_back(typename ConnectionType::PrivateTag{}, block);
            }
        }
        // the deleted copy and move operations

        /// Cancels every timer, returns every held packet and drops every queued one, which goes back to its pool
        /// now or when the device returns it; the IP brick and the wheel outlive it.
        ~Stack() {
            for (Block& block : context_.blocks) {
                transmitter_.disarm(block);
                block.prepared.reset();
                block.receive.release(context_.pool);
                transmitter_.drop_queue(block);
            }
        }

        /// Records the stamp, publishes deferred retry hints, then processes each datagram. Every packet is moved
        /// out or released. An empty span is valid.
        void process(const std::span<net::Datagram<Packet>> segments, const core::TimePoint now) noexcept {
            context_.now = now;
            for (Block* block = transmitter_.pop_retry(); block != nullptr; block = transmitter_.pop_retry()) {
                lifecycle_.raise(*block, stream::Event::Writable);  // the deferred retry hint, at most one per marked connection
            }
            for (Datagram& datagram : segments) {
                if (datagram.packet.empty()) {
                    continue;
                }
                receiver_.on_datagram(datagram);
                if (!datagram.packet.empty()) {
                    datagram.packet = Packet{};  // not held: back to the pool now, not at IP's next process
                }
            }
        }
        [[nodiscard]] std::optional<EventType> poll_event() noexcept;   // lifecycle_.pop_event, then as today
        void flush(const core::TimePoint now) noexcept;                 // as Task 5 left it
        [[nodiscard]] std::expected<void, ListenError> listen(std::uint16_t port) noexcept;   // lifecycle_
        void unlisten(std::uint16_t port) noexcept;                                            // lifecycle_
        [[nodiscard]] std::expected<ConnectionType*, ConnectError> connect(Endpoint peer, core::TimePoint now) noexcept;  // as Task 5 left it
        // connection(index) both overloads, capacity, mss, byte_budget, counters, config, listening, pending_events,
        // now, nodes_available, table_size, sent_segment, send_nodes_available, force_next_isn, force_recover:
        // one line each over context_, lifecycle_, transmitter_ or the handle's block_, as Tasks 3 to 5 left them.

    private:
        friend class Connection<Ip, CongestionControl>;

        using Block       = detail::ControlBlock<Ip, CongestionControl>;
        using Datagram    = net::Datagram<Packet>;
        using Transmitter = detail::Transmitter<Ip, CongestionControl>;

        /// The wheel's callback: the node's block, then the Lifecycle's timer handling.
        static void on_timer_fired(loop::Timer& timer) noexcept {
            Block& block = static_cast<typename Block::TimerNode&>(timer).block;
            block.stack.lifecycle_.on_timer(block);
        }

        // The handle's verbs.
        [[nodiscard]] typename ConnectionType::View unread(const Block& block) const noexcept { return block.receive.view(context_.pool); }
        void consume(Block& block, const std::size_t count) noexcept { receiver_.consume(block, count); }
        [[nodiscard]] std::size_t writable(const Block& block) const noexcept { return transmitter_.writable(block); }
        [[nodiscard]] std::optional<std::span<std::byte>> prepare(Block& block, const std::size_t count) noexcept { return transmitter_.prepare(block, count); }
        [[nodiscard]] bool commit(Block& block, const std::size_t count) noexcept { return transmitter_.commit(block, count); }
        void close(Block& block) noexcept { lifecycle_.close(block); }
        void abort(Block& block) noexcept { lifecycle_.abort(block); }
        void release(Block& block) noexcept { lifecycle_.release(block); }

        detail::StackContext<Ip, CongestionControl> context_;
        detail::Transmitter<Ip, CongestionControl> transmitter_;
        detail::Lifecycle<Ip, CongestionControl> lifecycle_;
        detail::Receiver<Ip, CongestionControl> receiver_;
```

Replace the "**One class per concern.**" paragraph (including Task 1's folder sentence) with:

> **One class per concern.** `tcp::Stack` is the brick's façade and owner: the four verbs, the accessors, and the mapping from a connection's state to its public handle. What it does is three procedure classes in `tcp::detail`, each in its own header under `detail/`, over one `detail::ControlBlock` per connection, RFC 9293's transmission control block as a struct with one part per concern, and one `detail::StackContext` per shard, what every part reads: the IP brick, the config, the held-segment pool, the counters and the stamp. The `Receiver` is what a datagram does to a connection: the checksum and lookup, the handshake, RFC 9293's order on a synchronized connection, the ACK processing that drives loss recovery, and `consume`; it owns nothing. The `Lifecycle` owns the connection table, the ISN generator and the event list: slots in and out, the states to `Closed`, `close`, `abort`, `release`, and the timer expiries that resend or give up. The `Transmitter` owns the segment writer, the send pool and the ACK, retry and deferred lists: every segment that leaves, the retransmission queue's entries, the resends with the busy rule and the copy, the pure ACKs, probes and resets, the timers' arming, and `writable`, `prepare`, `commit`. The dependency runs one way, Receiver → Lifecycle → Transmitter, read off the includes, as Linux's `tcp_input.c` and `tcp_timer.c` call into `tcp_output.c` and not back; the triggers from the receive side (an immediate ACK, a fast retransmit, the SYN-ACK) are direct calls, and state defers work only where it must wait anyway: the ordinary ACK until `flush`, the retry hint until the next `process`, a resend whose packet is lent until the next `flush`. The block is plain single-thread memory: a connection's receive and transmit run on one shard thread, and nothing in it is shared. Beneath the three: per shard `ConnectionTable`, `SegmentWriter`, `IsnGenerator` and one `NodePool` each for held packets and retransmission-queue entries; per connection `ReceiveQueue`, `AckPolicy`, `SendSequence`, `RetransmissionQueue`, `LossRecovery` (over the policy's state), `RttEstimator`, `ZeroWindowProbe` and `Timestamps`. The folders: `detail/` holds every part, included as `<detail/name.hpp>`; `connection/` the handle and its read view; `stack/` the façade and the forward header; `config/` the configuration and counters; `congestion/` the policies; `table/` the flow table.
